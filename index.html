      How does this work?

      Entropy measures how unpredictable a password is, in bits. It is estimated as effective length × log₂(character pool size). The effective length is reduced for repeated characters, sequences like “abc” or “1234”, keyboard patterns, years, and dictionary words (including look-alike substitutions such as “@” for “a”). Every extra bit doubles the guesses an attacker needs. Very common passwords are capped at a very low score.

      Leak check (k-anonymity): your browser computes the SHA-1 hash of the password and sends only its first 5 characters to the Have I Been Pwned range API. The service returns every hash suffix that shares that prefix, and your browser looks for a match locally. The server never learns the password or even the full hash.

      Generator: everything is created with crypto.getRandomValues, the browser’s cryptographically secure random source, using rejection sampling to avoid modulo bias. Passwords include at least one character of each selected type. Passphrase strength is words × log₂(word list size), which assumes the attacker knows the word list, so longer phrases are safer.

      Limits: scores and crack times are estimates for comparison. Real attackers use smarter strategies, so use a unique password for every account and a password manager. Never type your real passwords into any online tool.
